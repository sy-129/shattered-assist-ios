# 辅助功能的源码依据与验证

上游基线：57a4e06a4caf162446d1c28caa7983f0493fecf0（4.0.2）。这是开放源码修改，不依赖对另一个进程做内存扫描。

## 伤害路径

Hero.damageRoll 原来先选择当前武器或徒手随机伤害，再加入相关增益，最后返回整数。修改在最终返回点调用 AssistRules.weaponDamage。倍率因此只应用一次，并保留原有随机数、武器计算和后续敌人防御处理。中间运算使用 long，最终饱和到 Integer.MAX_VALUE，避免溢出变为负伤害。倍率白名单为1/2/5/10，无效配置回退1。独立法杖伤害入口未改。

## 生存路径

Hero.damage 在正伤害进入原有生命处理前检查开关，开启时提前返回。它不会拦截直接设置 HP、调用 die 或剧情结算，因此菜单采用“阻止生命伤害”而非保证永不死亡。

Hunger.act 开启辅助时清空 level/partialDamage 并照常 spend(TICK)，避免跳过时间调度造成死循环；affectHunger 同样拦截饥饿增长。关闭后恢复原逻辑，不返还已经吃掉的食物。

## UI 与状态

GameScene 创建游戏所有的 AssistButton，使用现有 uiCamera。按钮点击仅在角色存活、轮到玩家且没有其他窗口时打开 WndAssist；长按切换左右位置。窗口使用游戏现有 ScrollPane，横屏空间不足时滚动。

选项通过 SPDSettings 保存，并缓存为 volatile 字段，供角色线程读取；GameScene 创建时加载。默认1倍、不免伤、不免饥饿；“关闭全部辅助”可恢复。回血按钮只在角色存活且 ready 时修改 HP=HT，不消费道具、不复活、不清除异常状态。

## 自动验证范围

core/src/test/.../AssistIntegrationTest.java 包含6个测试：

- 设置保存、重载、重置；
- 伤害零值、负值、无效倍率和整数溢出边界；
- 真实 Hero.damageRoll 在25个随机种子和4档倍率下的100次比较；
- 真实匕首武器入口的倍率比较；
- 真实 Hunger 的饥饿拦截、tick执行和关闭后恢复；
- 真实 Hero.damage 对致命正伤害的拦截。

这些验证玩法入口，不代表触摸、字体、音频、存档或iOS27.0.1启动已实测。IPA还需在设备上完成以下验收。

## 实机步骤

1. 使用有效证书/描述文件在轻松签签名安装，记录设备、系统构建号和包哈希。
2. 打开游戏创建新角色，确认能进入第一层。
3. 点击辅助，切换倍率、免伤和免饥饿，观察角色攻击、受伤和食物状态；分别关闭后再验证。伤害有随机性和防御减免，不能只用单次攻击判断倍率。
4. 受伤后回血，确认HP恢复；长按辅助切换侧边，横竖屏确认菜单可滚动、关闭。
5. 退出再打开，确认设置和游戏存档可读；关闭全部辅助，确认恢复默认。
